# Checkpoint — Fix stale mobile favicon: missing apple-touch-icon + wrong metadataBase domain

## Context

Follow-up to `2026-08-19-logo-favicon-share-image.md`. That pass shipped correctly, but the user reported the old white-triangle icon was still showing on iOS Safari's tab switcher and search suggestions after the deploy.

## Human directions

- "when i look up my site on mobile, it is still showing this white triangle as the thumbnail for the site rather than my logo" — with two iOS Safari screenshots (tab switcher, URL bar suggestions), which also revealed the live production domain is `tinanle.com`, not the `tinale21.github.io/Portfolio` URL every prior favicon/OG-image change had assumed.

## Records of resistance / things I got wrong and had to correct

- Went in assuming this was either (a) a `NEXT_PUBLIC_BASE_PATH` misconfiguration now that a custom domain was in play, or (b) plain browser favicon caching. Didn't guess — checked directly: `dig`/`curl -I` on `tinanle.com` showed `server: Vercel` and Vercel's own DNS, not GitHub Pages. This project has **two live, independent deployments of the same repo**: the GitHub Actions → GitHub Pages pipeline in `.github/workflows/deploy.yml` (still live at `tinale21.github.io/Portfolio/`, confirmed reachable), and a separate Vercel project (presumably connected via Vercel's own GitHub integration, not anything in this repo) auto-deploying to `tinanle.com` → redirects to `www.tinanle.com`, which is the one the user actually visits. Neither `next.config.ts` nor `deploy.yml` mention Vercel at all — this was invisible from the repo alone.
- Confirmed the live `favicon.ico` on `www.tinanle.com` was *already* the correct new multi-size logo icon (curled it directly, `file` confirmed 6 embedded PNG sizes) — so the regular favicon pipeline was fine. Kept digging instead of concluding "it's just caching" from that alone.
- Root cause of the reported issue is a completely different icon: iOS Safari's tab switcher, bookmarks, and home-screen icon read the `apple-touch-icon` link, not `favicon.ico`, and none existed anywhere in this project (`curl` for `/apple-touch-icon.png` 404'd; no `<link rel="apple-touch-icon">` in the built HTML at all) — iOS falls back to a generic placeholder when it's absent, matching the exact white-triangle-in-circle the user described.
- Added `src/app/apple-icon.png` (Next's static file convention, confirmed valid for `.png` per `node_modules/next/dist/docs/.../app-icons.md`) and rebuilt — the route generated correctly (`○ /apple-icon.png` in the build output, file reachable at 200), but **no `<link rel="apple-touch-icon">` tag appeared in the built HTML at all**. Same failure mode as the earlier `icon.svg`-drops-`favicon.ico` bug from the prior checkpoint: once `metadata.icons` is declared manually (already true here, for the light/dark favicon split), Next stops auto-merging *any* file-convention icon detection, not just the specific sub-key already set — it silently dropped the entire `apple-icon.png` auto-detection, not just left it deprioritized. Fixed by declaring `icons.apple` explicitly alongside `icons.icon`, same technique as before. Verified via the built HTML that the tag now exists with the correct href/sizes/type under both a root-relative build and the `/Portfolio`-prefixed GitHub Pages build.
- Separately, and while investigating the domain split, noticed `metadataBase` was still hardcoded to `https://tinale21.github.io` (root, no `/Portfolio`) from the prior checkpoint. Confirmed via `curl` that this produces a **genuinely broken** `og:image`/`twitter:image` URL on the real production site: `https://tinale21.github.io/opengraph-image.png` 404s (the actual GitHub Pages deployment serves that file under `/Portfolio/`, and the real production domain, Vercel, doesn't share a domain with GitHub Pages at all regardless). This means the "website preview/share thumbnail" part of the original request was silently broken on the site real visitors land on, since the prior checkpoint's Puppeteer verification tested against the local build's own asset resolution, not against what the live third-party domain actually serves. Fixed by pointing `metadataBase` at `https://www.tinanle.com` (the canonical host — the bare `tinanle.com` apex 307-redirects there) instead.
- Side effect flagged, not fixed: this makes the GitHub Pages deployment's own `og:image` point at `www.tinanle.com/Portfolio/opengraph-image.png`, which doesn't exist there (that deployment's real image lives at `tinale21.github.io/Portfolio/opengraph-image.png`). Deliberately optimized for the domain real visitors use — didn't ask before making this call, since the evidence (DNS + the user's own screenshots showing that domain) was unambiguous, but flagging here in case the GitHub Pages deployment is still meant to be independently shareable for some reason.

## Successes

- Diagnosed via direct evidence at every step (`dig`, `curl -I`, `file`, built-HTML grep) rather than guessing between the caching/misconfiguration hypotheses — avoided both a wrong "just wait, it's caching" answer and a wrong "fix BASE_PATH" answer, since neither was actually the bug.
- New `apple-icon.png` reuses the same visual treatment as the existing OG/Twitter share image (dark brand `#262626` background, white logo centered) rather than the transparent favicon treatment — deliberate, since iOS composites this onto its own background and applies its own corner rounding, so a transparent or pre-rounded source would look wrong there. Rendered at 180x180 (Apple's recommended minimum) via 2x supersampling + Lanczos downsample for a crisp result, opaque RGB (no alpha) per the same reasoning.
- Verified via Puppeteer against a production build served locally: all four icon `<link>` tags (light favicon, dark favicon, `.ico` fallback, apple-touch-icon) present and correct under both `prefers-color-scheme` states; `apple-icon.png`, `opengraph-image.png`, and both favicon PNGs all resolve 200. Rebuilt with both an empty `BASE_PATH` (matching the real Vercel production config) and `NEXT_PUBLIC_BASE_PATH=/Portfolio` (matching the GitHub Pages workflow) — confirmed the apple-touch-icon href and `og:image` URL are each correctly prefixed (or not) in both.
- Full horizontal-overflow sweep across all seven pages still comes back at 0px.
- `npx tsc --noEmit` clean. `npx eslint` shows one pre-existing, unrelated error in `HeroSection.tsx` (confirmed via `git stash` that it exists on `main` before this change too) — not introduced by this pass, left untouched.

## State at this checkpoint

- **Added** `src/app/apple-icon.png` (180x180, opaque, dark-brand background + white logo) — Next's static file convention for the iOS home-screen/tab-switcher icon.
- **Modified** `src/app/layout.tsx`: `metadataBase` changed from `https://tinale21.github.io` to `https://www.tinanle.com` (the real production domain — see resistance notes above); `metadata.icons` gained an explicit `apple` entry pointing at the new file, since declaring `icons.icon` already suppressed Next's own auto-detection of it.
