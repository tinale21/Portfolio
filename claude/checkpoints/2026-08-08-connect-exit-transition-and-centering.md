# Checkpoint — Connect's exit transition, true viewport centering

## Context

A long iterative round getting the Connect → Experiences handoff to match the reference's "heading scrolls behind the next section" look, plus a real centering bug this work surfaced along the way.

## Human directions

- "i want it to scroll into the next section more smoothly" — pointed back at the motion reference video and live site, specifically calling out that the text appears to scroll and disappear *into* the next section (not just exit cleanly on its own).
- After a first fix (native-scroll-away, no double motion): "it still doesn't seem to work at the end... it appears that the text goes behind the next section when scrolled" — clarifying the actual desired effect is occlusion (next section visibly covering the heading), not just a clean exit.
- After the covering effect worked: "umm there is some errors going on" + a screenshot showing the Client Logos marquee rendering inside Connect's dark section, overlapping "Let's Connect" — a real regression from overshooting the overlap amount.
- After that was fixed: "it's getting better. I don't think the 'Let's Connect' text is centered. I also don't think the card stack section in the starting position is centered anymore" — flagging both sections independently, without being asked to look at Philosophy at all.
- After centering was fixed: "it is centered now but now the 'Let's Connect' text isn't going behind the next section when scrolled down" — the centering fix silently broke the exit effect's timing, since the two were coupled without either side knowing it.
- "can you make the black section... more shorter because there is a long section after there are no more photos that feels too long" — with a screenshot showing a mostly-empty dark screen.
- "let's build and push".

## Records of resistance / things I got wrong and had to correct

- **First exit-transition attempt**: assumed the reference's "text scrolls and disappears" was just a clean native-scroll exit (heading detaches from its sticky pin and scrolls away like normal content). Verified this made the timing internally consistent (no double-motion) but the user immediately clarified this wasn't the actual desired effect — the reference shows the heading getting *occluded* by the incoming section, not just exiting on its own. Should have looked more carefully at what "goes behind" implies before assuming "exits cleanly" was equivalent.
- **Second attempt, overlap math error**: derived a negative-margin "pull" amount for Experiences to overlap Connect's tail and cover the heading. First derivation gave 1427px minimum — used 1450px. This overshot Experiences' own natural content height (measured at 780px), so the overlap "ate through" Experiences entirely and dragged Client Logos (the next sibling) up into Connect's still-active wrapper — a real, user-visible bug caught via screenshot, not caught by my own verification (I'd verified the covering effect in isolation but hadn't checked what happened to sections *after* Experiences). Redid the algebra carefully and found the correct minimum was actually 527px, not 1427px — an arithmetic error in the first pass, not just an unlucky choice of margin.
- **Fixed PULL/HOLD broke on the centering fix**: after correctly implementing the cover effect with fixed px constants (tuned against a 1512x900 test viewport), fixed the *actual* centering bug the user reported (heading/cluster centered relative to the aspect-ratio box's own height, not the real browser viewport — measured ~41px and ~26.5px offsets). That fix moved the heading's on-screen position, which silently invalidated the fixed PULL/HOLD constants' correctness — didn't anticipate this coupling until the user reported the exit effect broke again. Fixed properly this time by deriving both values from live viewport dimensions via a shared `getConnectExitTiming` function, and verified across 5 different viewport sizes (700-1080px tall) before calling it done, instead of re-tuning against one viewport again.

## Successes

- For every timing claim in this round, verified via actual Puppeteer measurement (scroll to a computed offset, check `elementFromPoint` / `getBoundingClientRect`) rather than trusting the algebra alone — this is what caught the Client Logos bleed-through, the arithmetic error in the pull threshold, and confirmed the final fix works across multiple viewport sizes, not just one.
- When the user flagged Philosophy's centering as a *separate* issue I hadn't touched, diagnosed it as the identical root cause (aspect-ratio-box-relative centering vs. true viewport centering) rather than treating it as an unrelated one-off — fixed both with the same technique (converting a desired true-viewport px position into the existing Figma-px coordinate system each component already used, rather than restructuring either component's layer architecture).
- Recognized the PULL/HOLD coupling between ConnectSection and ExperiencesSection needed to live in one shared, viewport-parameterized function (`getConnectExitTiming` in connect-data.ts) rather than two independently-tuned constants, specifically *because* the first version's failure mode (silently breaking when an unrelated fix changed the heading's position) was a direct symptom of that coupling not being made explicit.

## State at this checkpoint

- **Connect → Experiences exit**: Experiences pulls up over Connect's tail via a *dynamically computed* negative margin (`pull`, from `getConnectExitTiming`), and Connect holds its heading pinned for a correspondingly dynamic extra scroll distance (`hold`) past when photos finish animating. Both derive from live `window.innerWidth`/`innerHeight` on mount and resize — no more fixed px constants tuned against one test viewport. Verified across 5 viewport sizes (1512x900, 1512x700, 1512x1000, 1200x800, 1920x1080): heading always gets covered while still perfectly stationary, no premature reveal before photos finish, no bleed-through into Client Logos.
- Safety margins (`PULL_MARGIN`, `REVEAL_MARGIN`) tightened from 100px to 20px each per feedback that the dead stretch (photos gone, nothing else on screen yet) felt too long — cut it by ~150-200px across tested viewports.
- **Centering**: both Connect's heading and Philosophy's photo cluster + quote now resolve to the true viewport center (`window.innerHeight/2`) rather than 50%/a fixed percentage of their aspect-ratio container's own (width-derived, viewport-height-independent) height. `PhilosophyImage` now takes `clusterCenterY` as a prop instead of importing the static Figma constant directly.
- `NavBar`'s theme-detection loop now iterates DOM matches in reverse (last match wins) instead of forward (first match wins), needed because the Connect/Experiences overlap means two `[data-nav-theme]` sections can legitimately straddle the nav's bottom edge at once — the later one in DOM order is the one actually painted on top.
